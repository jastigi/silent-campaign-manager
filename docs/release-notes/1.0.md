# Release 1.0 — Campaign Simulator

## Campaign Simulation Foundation

- Added `CampaignSimulationService`.
- Added `CampaignSimulationServiceImpl`.
- Added immutable `CampaignSimulationResult`.
- Campaigns can coordinate all their patrol simulations.
- Patrols are executed by patrol date and identifier.
- Tactical execution remains delegated to `SimulationService`.
- Existing tactical evaluation and persistence are reused unchanged.
- Empty campaigns return a valid result with zero patrols.
- Campaign execution currently follows a synchronous fail-fast strategy.
- Added automated tests for orchestration order, empty campaigns,
  missing campaigns and interrupted execution.
- Added ADR-001 documenting campaign-to-patrol delegation.

## Campaign Progression

- Added immutable `CampaignProgress`.
- Added `CampaignProgressService`.
- Campaign progress is derived from existing patrols and persisted
  simulation records.
- Completed patrols are counted distinctly.
- Repeated simulations do not increase completion incorrectly.
- Added total, completed and pending patrol counts.
- Added completion percentage rounded to two decimal places.
- Added campaign completion status.
- Empty campaigns report zero-percent progress and remain incomplete.
- Integrated campaign progression into `CampaignSimulationResult`.
- Added ADR-002 documenting derived campaign progression.

## Campaign Statistics

- Refactored the existing campaign statistics module.
- Campaign statistics now use persisted `SimulationRecord` data.
- Added distinct completed-patrol metrics through campaign progression.
- Added total historical simulation count.
- Added successful, partially successful and failed simulation totals.
- Added campaign success rate.
- Added average tactical mission score using real persisted scores.
- Added contacts detected and contacts lost totals.
- Added intelligence-gathered totals.
- Added incident totals.
- Removed the unused fixed `averageRisk` value.
- Removed estimated scoring based on `PatrolResult`.
- Preserved the existing campaign statistics REST endpoint.
- Added service, mapper, controller and repository test coverage.

## Campaign Lifecycle Design

- Defined the Release 1.0 campaign lifecycle.
- Preserved the existing `ACTIVE`, `FINISHED` and `ABANDONED` statuses.
- Defined valid and invalid campaign transitions.
- Defined `FINISHED` and `ABANDONED` as terminal states.
- Defined campaign completion through derived campaign progression.
- Established that only active campaigns may execute new simulations.
- Established that empty campaigns cannot be finished.
- Decided not to introduce State Pattern before state-specific behaviour
  justifies it.
- Added ADR-003 documenting lifecycle transition architecture.
- Added the campaign lifecycle design document.
