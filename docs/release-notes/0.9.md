# Release 0.9 — Operational Simulation

Release 0.9 expands the simulation engine with environmental, sonar and tactical operational mechanics.

This release is currently under development.

---

## Added

### Weather Engine

- Added `WeatherCondition`.
- Added `SeaState`.
- Added `WeatherReport`.
- Added the `WeatherGenerator` abstraction.
- Added `RandomWeatherGenerator`.
- Weather conditions are generated at the beginning of each simulation.
- Generated weather is stored in `SimulationContext`.
- Weather generation is recorded in the simulation timeline.
- Added `WeatherDetectionModifier`.
- Weather conditions now influence contact detection.
- Added probability limits from 0 to 100.
- Final detection probability is recorded in the simulation timeline.
- Added unit coverage for every weather condition and boundary value.
- Added `SeaStateDetectionModifier`.
- Sea state now influences final contact detection probability.
- Added unit coverage for all supported sea states and probability boundaries.
- Added `WeatherClassificationModifier`.
- Weather now influences contact classification probability.
- Integrated environmental conditions into `ClassificationCalculator`.
- Added unit coverage for weather classification effects.
- Added the `Visibility` environmental model.
- Weather reports now include visibility conditions.
- Visibility now influences contact classification probability.
- Weather timeline events now expose generated visibility.
- Completed the initial Weather Engine.

## Planned

### Weather Engine

- Sea-state influence on contact detection.
- Weather influence on contact classification.
- Visibility model.

### Sonar Engine

- Passive detection.
- Active sonar.
- Acoustic signatures.
- Added `PassiveSonarDetectionModifier`.
- Passive sonar effectiveness now depends on submarine role.
- SSN platforms receive a detection bonus.
- SSBN platforms receive a small detection penalty.
- Replaced the previous generic submarine detection modifier.
- Added active sonar as a secondary detection attempt.
- Active sonar is restricted to appropriate mission types.
- Added active-sonar success and failure timeline events.
- Added automated coverage for active-sonar availability and detection.
- Added the `AcousticSignature` model.
- Assigned acoustic signatures to every supported submarine class.
- Acoustic signature now influences passive sonar detection.
- Combined platform role and acoustic performance in the passive sonar model.
- Added automated coverage for all acoustic-signature levels.
- Completed the initial Sonar Engine.

### Tactical AI

- Contact behaviour.
- Classification decisions.
- Shadowing.
- Contact evasion.
- Added the `ContactBehaviour` model.
- Added threat-based contact behaviour resolution.
- Added a dedicated contact behaviour simulation phase.
- Contact tactical behaviour is now recorded in the simulation timeline.
- Added automated coverage for behaviour resolution and phase execution.
- Added `ShadowingDecisionResolver`.
- Patrols now decide whether to begin shadowing classified contacts.
- Shadowing decisions are recorded in the simulation timeline.
- Added TrackingResolver.
- Added TrackingPhase.
- Patrols can now establish or lose tracking of shadowed contacts.
- Tracking events are recorded in the simulation timeline.
- Added `ContactLossResolver`.
- Added `ContactLossPhase`.
- Shadowed contacts are now marked as lost when tracking fails.
- Contacts that were not selected for shadowing are not counted as lost.
- Lost contacts increment the simulation `contactsLost` counter.
- Contact-loss events are recorded in the simulation timeline.
- Added automated coverage for contact-loss resolution and phase execution.
- Added `IntelligenceGatheringResolver`.
- Added `IntelligenceGatheringPhase`.
- Classified and actively tracked contacts can now provide useful intelligence.
- Lost contacts cannot provide intelligence.
- Intelligence gathering requires a confidence level of at least 60.
- Added the `intelligenceGathered` state to detected contacts.
- Added the simulation intelligence counter to the REST response.
- Added `INTELLIGENCE_GATHERED` timeline events.
- Updated `IntelligenceSuccessStrategy` to use the operational intelligence result.
- Added automated tests for intelligence gathering and mission outcome integration.

### Mission Evaluation

- Dynamic mission scoring.
- Operational success calculation.

### Tactical Mission Evaluation

- Added `TacticalMissionEvaluator`.
- Added `TacticalMissionEvaluatorImpl`.
- Added `TacticalMissionEvaluation`.
- Centralized post-simulation outcome, score, report and debrief generation.
- Simplified `SimulationServiceImpl`.
- Preserved the separation between pre-mission risk evaluation and post-simulation tactical evaluation.
- Added automated coverage for tactical mission evaluation orchestration.

### Simulation Persistence

- Added the `SimulationRecord` persistence entity.
- Added the stable `SimulationOutcome` persistence enum.
- Added `SimulationRecordRepository`.
- Added `SimulationRecordMapper`.
- Added `SimulationPersistenceService`.
- Completed simulation summaries are now persisted automatically.
- Stored simulation data includes mission outcome, mission score, contact statistics, intelligence, incidents, completion date, report summary and debrief.
- Transient simulation objects are not persisted directly.
- Added mapper, service and JPA repository tests for simulation persistence.
- Preserved the existing simulation REST response contract.
